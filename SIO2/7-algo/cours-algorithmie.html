L'algorithmique

Module : AlgorithmiqueNiveau : BTS SIO 2e année

Un programme, quel que soit le langage, n'est que la traduction d'un algorithme : une suite d'instructions qui transforme des données d'entrée en un résultat. Savoir programmer, c'est d'abord savoir écrire cet algorithme ; le langage vient après.

Ce module tient sur six notions : les variables, les conditions, les boucles, les tableaux, les fonctions, et pour finir les algorithmes classiques de recherche et de tri. Chacune est présentée en pseudo-code, la notation utilisée à l'examen, puis traduite en C#, le langage de vos projets.

Chaque chapitre de théorie est immédiatement suivi de son TP : on n'accumule jamais deux notions sans les avoir pratiquées.

Pourquoi le pseudo-code si l'on programme en C# ?

Parce que le pseudo-code ne se compile pas : il oblige à réfléchir au raisonnement au lieu de se battre avec la syntaxe. Un algorithme juste se traduit dans n'importe quel langage en quelques minutes ; un algorithme faux ne se répare dans aucun langage.

Partie théorique

1.1 : Qu'est-ce qu'un algorithme ?

Algorithme

Suite finie et ordonnée d'instructions non ambiguës (ou non interpretable) qui, à partir de données d'entrée, produit un résultat.

Trois propriétés, toujours :

PropriétéCe que cela impose
Finiil se termine, en un nombre connu d'étapes
Précischaque instruction a un sens unique, pas d'interprétation
Effectifchaque instruction est réalisable par la machine

Une recette de cuisine est un algorithme. « Salez à votre goût » n'en est pas une instruction : ce n'est pas précis.

1.2 : La structure d'un algorithme

Trois parties, dans cet ordre.

Algorithme CalculTTC          ← 1. le nom

Variables
    prixHT   : Réel           ← 2. les déclarations
    prixTTC  : Réel

Début                         ← 3. le corps
    Écrire("Prix HT ?")
    Lire(prixHT)
    prixTTC ← prixHT * 1.20
    Écrire("Prix TTC : ", prixTTC)
Fin

Le même programme en C# :

using System;

class Program
{
    static void Main()
    {
        double prixHT;
        double prixTTC;

        Console.WriteLine("Prix HT ?");
        prixHT = double.Parse(Console.ReadLine());
        prixTTC = prixHT * 1.20;
        Console.WriteLine("Prix TTC : " + prixTTC);
    }
}
Ce que C# ajoute et que le pseudo-code ignore

using, class, static void Main : ce sont des contraintes du langage, pas de l'algorithme. On les écrit une fois et on n'y pense plus. En pseudo-code, Début et Fin suffisent.

1.3 : Les variables et les types

Variable

Emplacement nommé de la mémoire, qui contient une valeur d'un type donné et dont le contenu peut changer pendant l'exécution.

Une variable a trois caractéristiques : un nom, un type, une valeur.

Nommer une variable : les règles qui évitent les ennuis :

  • un nom parlant : nbEtudiants, pas n ni x ;
  • pas d'accent, pas d'espace, pas de caractère spécial ;
  • l'usage en C# est le camelCase : première lettre minuscule, majuscule à chaque mot suivant.

La division entière, le piège classique

En C#, 7 / 2 vaut 3 et non 3.5 : deux entiers divisés donnent un entier, la partie décimale est jetée. Pour obtenir 3.5, il faut au moins un réel : 7.0 / 2.

Priorité: comme en mathématiques : *, /, % avant + et -. En cas de doute, mettez des parenthèses pour les priorités.

En mathématiques, rien ne doit être soumis à interprétation dans un raisonnement. En algo, c'est pareil Mettez des parenthèses !!! 
moyenne ← (note1 + note2 + note3) / 3     ← les parenthèses sont indispensables

Partie théorique

3.1 : Le test simple

Une condition est une expression qui vaut Vrai ou Faux. Si elle est vraie, le bloc s'exécute.

Si age >= 18 Alors
    Écrire("Majeur")
Sinon
    Écrire("Mineur")
FinSi
if (age >= 18)
{
    Console.WriteLine("Majeur");
}
else
{
    Console.WriteLine("Mineur");
}

Le Sinon est facultatif : sans lui, rien ne se passe quand la condition est fausse.

Les accolades ne sont pas décoratives

En C#, sans accolades, if ne contrôle que la première instruction qui suit. Le code ci-dessous affiche toujours « Bienvenue », même à un mineur :

if (age >= 18)
    Console.WriteLine("Majeur");
    Console.WriteLine("Bienvenue");   // hors du if !

Mettez toujours les accolades, même pour une seule ligne.

Un booléen se teste directement

Si possedePermis = Vrai est correct mais lourd. Si possedePermis dit la même chose. De même, Si NON possedePermis remplace Si possedePermis = Faux.

Un intervalle s'écrit avec deux comparaisons. Si 0 <= note <= 20 n'existe pas en C# ; il faut écrire :

if (note >= 0 && note <= 20)

3.3 : Les tests enchaînés

Quand il y a plus de deux cas, on enchaîne avec SinonSi :

Si note >= 16 Alors
    mention ← "Très bien"
SinonSi note >= 14 Alors
    mention ← "Bien"
SinonSi note >= 12 Alors
    mention ← "Assez bien"
SinonSi note >= 10 Alors
    mention ← "Passable"
Sinon
    mention ← "Ajourné"
FinSi
if      (note >= 16) mention = "Très bien";
else if (note >= 14) mention = "Bien";
else if (note >= 12) mention = "Assez bien";
else if (note >= 10) mention = "Passable";
else                 mention = "Ajourné";
L'ordre des tests décide du résultat

Les conditions sont évaluées de haut en bas, et on s'arrête à la première vraie. Une note de 18 est bien >= 10, mais le test >= 16 la capture avant.

Inversez l'ordre, >= 10 en premier, et tout le monde est « Passable ». Le programme compile, s'exécute, ne signale rien, et se trompe systématiquement. Avec des seuils, on commence toujours par le plus restrictif.

3.4 : Le choix multiple

Quand on compare une même variable à des valeurs fixes, Selon est plus lisible qu'une cascade de SinonSi.

Selon jour Faire
    Cas 1 : Écrire("Lundi")
    Cas 2 : Écrire("Mardi")
    Cas 6, 7 : Écrire("Week-end")
    Autre : Écrire("Jour invalide")
FinSelon
switch (jour)
{
    case 1: Console.WriteLine("Lundi"); break;
    case 2: Console.WriteLine("Mardi"); break;
    case 6:
    case 7: Console.WriteLine("Week-end"); break;
    default: Console.WriteLine("Jour invalide"); break;
}
SinonSiSelon
Comparedes conditions quelconquesune variable à des valeurs
Convient pourdes intervalles (note >= 14)des valeurs exactes (jour = 2)
Le break est obligatoire en C#

Sans break, le compilateur refuse le programme. C'est une sécurité : dans d'autres langages, l'oubli fait exécuter le cas suivant sans prévenir.

Partie théorique

5.1 : La boucle Pour, quand on sait combien de fois

Pour i De 1 À 5 Faire
    Écrire("Tour numéro ", i)
FinPour
for (int i = 1; i <= 5; i++)
{
    Console.WriteLine("Tour numéro " + i);
}

Le for de C# contient trois parties, séparées par des points-virgules :

PartieRôleQuand
int i = 1initialisationune seule fois, au début
i <= 5condition de continuationavant chaque tour
i++incrémentationaprès chaque tour

i++ est un raccourci pour i = i + 1.

5.2 : La boucle TantQue, quand on ne sait pas

TantQue reponse ≠ "oui" Faire
    Écrire("Continuer ? (oui/non)")
    Lire(reponse)
FinTantQue
while (reponse != "oui")
{
    Console.WriteLine("Continuer ? (oui/non)");
    reponse = Console.ReadLine();
}

La condition est testée avant chaque tour : si elle est fausse dès le départ, le corps ne s'exécute jamais.

La boucle infinie

Si rien dans le corps ne fait évoluer la condition, la boucle ne s'arrête plus. Le programme se fige, il faut le tuer.

int i = 0;
while (i < 10)
{
    Console.WriteLine(i);   // i n'augmente jamais : boucle infinie
}

La vérification, avant d'exécuter : dans le corps de tout while, cherchez la ligne qui rapproche de la sortie. Si vous ne la trouvez pas, elle n'existe pas.

5.3 : La boucle Répéter, au moins une fois

Répéter
    Écrire("Entrez une note entre 0 et 20")
    Lire(note)
JusquÀ note >= 0 ET note <= 20
do
{
    Console.WriteLine("Entrez une note entre 0 et 20");
    note = int.Parse(Console.ReadLine());
} while (note < 0 || note > 20);

La condition est testée après : le corps s'exécute donc au moins une fois. C'est exactement ce qu'il faut pour une saisie : il faut bien demander une première valeur avant de pouvoir la vérifier.

La condition s'inverse entre les deux notations

Le pseudo-code dit JusquÀ condition de sortie ; le C# dit while condition de continuation. L'une est la négation de l'autre.

JusquÀ note >= 0 ET note <= 20 devient while (note < 0 || note > 20). Le ET devient OU en même temps que les comparaisons s'inversent : c'est la loi de De Morgan, et c'est une source d'erreur classique.

5.4 : Choisir sa boucle

La questionLa boucle
Je sais combien de fois (10 fois, une fois par élément)Pour
Je ne sais pas, et il se peut que ce soit zéro foisTantQue
Je ne sais pas, mais c'est au moins une foisRépéter

En pratique : Pour pour parcourir, TantQue pour attendre un événement, Répéter pour saisir.

5.5 : Les deux motifs à connaître

L'accumulateur : additionner au fil des tours. On l'initialise à 0 avant la boucle.

somme ← 0
Pour i De 1 À 10 Faire
    somme ← somme + i
FinPour
Écrire(somme)        ← 55

Le compteur : compter les cas qui remplissent une condition. Même principe.

nbPairs ← 0
Pour i De 1 À 20 Faire
    Si i MOD 2 = 0 Alors
        nbPairs ← nbPairs + 1
    FinSi
FinPour
L'initialisation, hors de la boucle

somme ← 0 avant le Pour. Placée à l'intérieur, elle remettrait le total à zéro à chaque tour, et le résultat vaudrait toujours la dernière valeur ajoutée.

Pour chercher un maximum, on initialise avec le premier élément, jamais avec 0 : sur des températures négatives, un maximum initialisé à 0 ne descend jamais en dessous.

Les boucles imbriquées : une boucle dans une boucle. La boucle intérieure fait un tour complet à chaque tour de l'extérieure.

Pour ligne De 1 À 3 Faire
    Pour colonne De 1 À 4 Faire
        Écrire("*")
    FinPour
    Passer à la ligne
FinPour

Trois lignes de quatre étoiles, soit douze affichages : 3 × 4. Deux boucles imbriquées multiplient le nombre de tours. Retenez-le, c'est le fondement du chapitre sur la complexité.

Partie théorique

7.1 : Déclarer un tableau

Tableau

Variable qui contient plusieurs valeurs de même type, rangées les unes à la suite des autres et accessibles par un indice.

Sans tableau, stocker 30 notes demanderait 30 variables. Avec, une seule suffit.

Variables
    notes : Tableau[0..29] de Entier
int[] notes = new int[30];              // 30 cases, toutes à 0
int[] notes = { 12, 15, 8, 17, 9 };     // 5 cases, valeurs fournies

L'indice commence à 0. Un tableau de 30 cases va de notes[0] à notes[29], jamais notes[30].

ÉcritureSens
notes[0]la première case
notes[4]la cinquième case
notes.Lengthle nombre de cases (5)
notes[notes.Length - 1]la dernière case
IndexOutOfRangeException

Accéder à notes[5] dans un tableau de 5 cases plante le programme à l'exécution. Le compilateur ne peut pas le détecter : il ne connaît pas la valeur de l'indice.

La dernière case est toujours à l'indice Length - 1. Le - 1 s'oublie, et c'est l'erreur la plus fréquente sur les tableaux.

7.2 : Parcourir un tableau

Avec Pour : on a l'indice, on peut modifier les cases :

Pour i De 0 À notes.Longueur - 1 Faire
    Écrire("Note ", i, " : ", notes[i])
FinPour
for (int i = 0; i < notes.Length; i++)
{
    Console.WriteLine("Note " + i + " : " + notes[i]);
}

Avec foreach : plus court, mais en lecture seule :

foreach (int note in notes)
{
    Console.WriteLine(note);
}
forforeach
L'indicedisponibleinaccessible
Modifier une casepossibleimpossible
Parcours partiel ou à l'enverspossibleimpossible
Quand l'utiliserdès qu'on a besoin de l'indicepour lire simplement
La condition s'écrit i < Length, pas i <= Length

Avec <=, la boucle irait jusqu'à l'indice Length, qui n'existe pas, et planterait au dernier tour. i < notes.Length couvre exactement 0 à Length - 1.

7.3 : Les quatre motifs de parcours

Presque tout ce qu'on fait sur un tableau est l'un de ces quatre motifs. Ils s'écrivent toujours de la même façon.

Additionner

int somme = 0;
for (int i = 0; i < notes.Length; i++)
    somme += notes[i];

Chercher le maximum

int max = notes[0];                     // on part du PREMIER élément
for (int i = 1; i < notes.Length; i++)
    if (notes[i] > max)
        max = notes[i];

Compter selon une condition

int nbAdmis = 0;
for (int i = 0; i < notes.Length; i++)
    if (notes[i] >= 10)
        nbAdmis++;

Chercher une valeur

bool trouve = false;
int position = -1;
for (int i = 0; i < notes.Length; i++)
{
    if (notes[i] == recherche)
    {
        trouve = true;
        position = i;
    }
}
Le maximum s'initialise avec le premier élément

int max = 0; semble naturel et donne un résultat faux dès qu'un tableau ne contient que des valeurs négatives : le maximum de {-5, -12, -3} serait annoncé à 0, une valeur qui n'est même pas dans le tableau.

On part de notes[0], et on commence la boucle à i = 1.

7.4 : Les tableaux à deux dimensions

Pour représenter un tableau de valeurs à double entrée : des notes par étudiant et par matière, une grille, une image.

Variables
    notes : Tableau[0..2][0..3] de Entier      ← 3 étudiants, 4 matières
int[,] notes = new int[3, 4];
notes[0, 2] = 15;                  // étudiant 0, matière 2

int[,] notes = { {12, 15, 8, 17},
                 {10, 9, 14, 11},
                 {18, 16, 13, 20} };

Le parcours demande deux boucles imbriquées :

for (int etu = 0; etu < 3; etu++)
{
    for (int mat = 0; mat < 4; mat++)
    {
        Console.Write(notes[etu, mat] + "\t");
    }
    Console.WriteLine();
}
ExpressionValeur
notes.GetLength(0)le nombre de lignes (3)
notes.GetLength(1)le nombre de colonnes (4)

Length sur un tableau 2D renvoie le nombre total de cases (12) : ce n'est presque jamais ce qu'on veut.

9.1 : Pourquoi découper

Un programme de 300 lignes d'affilée est illisible, impossible à tester, et le même calcul y est recopié trois fois. Le découper en sous-programmes apporte trois choses :

BénéficeConcrètement
Réutilisationle calcul est écrit une fois, appelé partout
LisibilitéCalculerMoyenne(notes) se lit ; dix lignes de boucle non
Correctionune erreur se corrige à un seul endroit

9.2 : Fonction ou procédure

Fonction

Sous-programme qui renvoie une valeur. On l'utilise dans une expression, comme une variable.

Procédure

Sous-programme qui ne renvoie rien. On l'appelle pour son effet : afficher, modifier, enregistrer.

Une fonction

Fonction Carre(n : Entier) : Entier
Début
    Retourner n * n
Fin
static int Carre(int n)
{
    return n * n;
}

int resultat = Carre(5);        // 25

Une procédure

Procédure AfficherLigne(longueur : Entier)
Début
    Pour i De 1 À longueur Faire
        Écrire("-")
    FinPour
Fin
static void AfficherLigne(int longueur)
{
    for (int i = 1; i <= longueur; i++)
        Console.Write("-");
    Console.WriteLine();
}

AfficherLigne(20);
FonctionProcédure
Renvoieune valeurrien

Contientun returnpas de return de valeur
S'utilisex = Carre(5);AfficherLigne(20);
Ne pas confondre afficher et retourner

Une fonction qui affiche son résultat au lieu de le retourner ne sert qu'une fois : on ne peut ni le stocker, ni le réutiliser dans un calcul.

static void Carre(int n) { Console.WriteLine(n * n); }   // inutilisable
static int  Carre(int n) { return n * n; }               // réutilisable

Règle : une fonction calcule et retourne ; c'est l'appelant qui décide d'afficher.

9.3 : Paramètres, arguments, portée

static int Addition(int a, int b)    // a et b : les PARAMÈTRES
{
    return a + b;
}

int total = Addition(3, 5);          // 3 et 5 : les ARGUMENTS

Le paramètre est le nom écrit dans la définition ; l'argument est la valeur donnée à l'appel. L'ordre compte : le premier argument va dans le premier paramètre.

Portée d'une variable

Zone du programme où la variable existe. Une variable déclarée dans une fonction n'existe que dans cette fonction : elle est créée à l'appel et détruite au retour.

static int Doubler(int n)
{
    int resultat = n * 2;       // resultat n'existe que dans Doubler
    return resultat;
}

static void Main()
{
    int x = Doubler(5);
    // Console.WriteLine(resultat);   ← ERREUR : resultat n'existe pas ici
}

C'est une protection : deux fonctions peuvent utiliser une variable i sans jamais se gêner.

9.4 : Par valeur ou par référence

Par défaut, C# passe les arguments par valeur : la fonction reçoit une copie. La modifier ne change rien à l'original.

static void Incrementer(int n)
{
    n = n + 1;                  // modifie la copie
}

int x = 5;
Incrementer(x);
Console.WriteLine(x);           // 5, et non 6

Avec le mot-clé ref, la fonction reçoit la variable elle-même :

static void Incrementer(ref int n)
{
    n = n + 1;
}

int x = 5;
Incrementer(ref x);
Console.WriteLine(x);           // 6
Mot-cléUsage
(rien)par valeur : la fonction lit, ne modifie pas
refla variable doit être initialisée avant l'appel, la fonction peut la modifier
outla variable n'a pas besoin d'être initialisée, la fonction doit l'affecter
Les tableaux font exception

Un tableau passé à une fonction est toujours modifiable, même sans ref. Ce qui est copié, c'est l'adresse du tableau, pas son contenu : les deux noms désignent alors les mêmes cases.

C'est pour cela que la fonction d'inversion du TP 4 modifie bien le tableau de l'appelant.

9.5 : Où écrire ses fonctions

En C#, les fonctions se déclarent dans la classe, à côté de Main, avec le mot-clé static.

class Program
{
    static void Main()
    {
        Console.WriteLine(Carre(5));
    }

    static int Carre(int n)
    {
        return n * n;
    }
}

L'ordre n'a pas d'importance : Main peut appeler une fonction écrite plus bas.

11.1 : La recherche séquentielle

On parcourt le tableau du début à la fin jusqu'à trouver la valeur.

C'est la seule recherche possible sur un tableau non trié.

11.2 : La recherche dichotomique

Sur un tableau trié, on peut faire beaucoup mieux : on regarde l'élément du milieu, et l'on élimine la moitié du tableau à chaque comparaison.

Fonction RechercheDichotomique(t : Tableau trié, valeur : Entier) : Entier
Variables
    debut, fin, milieu : Entier
Début
    debut ← 0
    fin   ← t.Longueur - 1

    TantQue debut <= fin Faire
        milieu ← (debut + fin) DIV 2
        Si t[milieu] = valeur Alors
            Retourner milieu
        SinonSi t[milieu] < valeur Alors
            debut ← milieu + 1          ← on cherche à droite
        Sinon
            fin ← milieu - 1            ← on cherche à gauche
        FinSi
    FinTantQue

    Retourner -1
Fin
static int RechercheDichotomique(int[] t, int valeur)
{
    int debut = 0;
    int fin = t.Length - 1;

    while (debut <= fin)
    {
        int milieu = (debut + fin) / 2;

        if (t[milieu] == valeur)     return milieu;
        else if (t[milieu] < valeur) debut = milieu + 1;
        else                         fin = milieu - 1;
    }
    return -1;
}

Le déroulé, sur {2, 5, 8, 12, 16, 23, 38, 56, 72, 91}, en cherchant 23 :

Tourdebutfinmilieut[milieu]Décision
10941616 < 23, on va à droite : debut ← 5
25975656 > 23, on va à gauche : fin ← 6
356523trouvé, on renvoie 5

Trois comparaisons au lieu de six pour la recherche séquentielle. Sur 1000 éléments, ce serait 10 au lieu de 500 ; sur un million, 20 au lieu de 500 000.

Deux conditions, et le tableau doit être trié

La dichotomie ne fonctionne que sur un tableau trié. Sur un tableau quelconque, elle ne plante pas : elle répond « absent » pour des valeurs présentes. Une erreur silencieuse, la pire espèce.

Et le + 1 / - 1 sur debut et fin sont indispensables : sans eux, si la valeur est absente, milieu ne bouge plus et la boucle devient infinie.

11.3 : Le tri par sélection

Le principe tient en une phrase : chercher le plus petit élément restant, et le mettre à sa place.

Procédure TriSelection(t : Tableau)
Variables
    i, j, indiceMin, temp : Entier
Début
    Pour i De 0 À t.Longueur - 2 Faire
        indiceMin ← i
        Pour j De i + 1 À t.Longueur - 1 Faire
            Si t[j] < t[indiceMin] Alors
                indiceMin ← j
            FinSi
        FinPour
        temp ← t[i]
        t[i] ← t[indiceMin]
        t[indiceMin] ← temp
    FinPour
Fin
static void TriSelection(int[] t)
{
    for (int i = 0; i < t.Length - 1; i++)
    {
        int indiceMin = i;
        for (int j = i + 1; j < t.Length; j++)
        {
            if (t[j] < t[indiceMin]) indiceMin = j;
        }
        int temp = t[i];
        t[i] = t[indiceMin];
        t[indiceMin] = temp;
    }
}

Le déroulé sur {5, 2, 9, 1} :

PasseOn cherche le min dansTrouvéAprès échange
1[5, 2, 9, 1]1[1, 2, 9, 5]
2[2, 9, 5]2[1, 2, 9, 5]
3[9, 5]5[1, 2, 5, 9]

La partie gauche est triée et définitive ; la partie droite rétrécit.

11.4 : Le tri à bulles

Autre principe : comparer les voisins deux à deux et les échanger s'ils sont dans le désordre. À chaque passe, la plus grande valeur « remonte » en fin de tableau.

static void TriBulles(int[] t)
{
    for (int i = 0; i < t.Length - 1; i++)
    {
        for (int j = 0; j < t.Length - 1 - i; j++)
        {
            if (t[j] > t[j + 1])
            {
                int temp = t[j];
                t[j] = t[j + 1];
                t[j + 1] = temp;
            }
        }
    }
}

Le - i de la boucle intérieure : après la passe 1, la plus grande valeur est déjà en place ; après la passe 2, les deux plus grandes. Inutile de les recomparer.

L'optimisation en une ligne

Si une passe complète n'a produit aucun échange, le tableau est trié : on peut sortir immédiatement.

bool echange = true;
for (int i = 0; i < t.Length - 1 && echange; i++)
{
    echange = false;
    for (int j = 0; j < t.Length - 1 - i; j++)
        if (t[j] > t[j + 1]) { /* échange */ echange = true; }
}

Sur un tableau déjà trié, le tri s'arrête après une passe au lieu de n.

11.5 : La complexité

Complexité

Ordre de grandeur du nombre d'opérations qu'un algorithme effectue, exprimé en fonction de la taille n des données. On la note O(...).

On ne compte pas les secondes (elles dépendent de la machine) mais les opérations, et on ne garde que le terme qui domine quand n grandit.

NotationNomExemplePour n = 1000
O(1)constanteaccéder à t[5]1
O(log n)logarithmiquerecherche dichotomique~10
O(n)linéairerecherche séquentielle, somme1 000
O(n²)quadratiquetri par sélection, tri à bulles1 000 000

Comment la reconnaître, en pratique :

Ce que vous voyez dans le codeComplexité
aucune boucleO(1)
une boucle sur les n élémentsO(n)
deux boucles imbriquées sur les n élémentsO(n²)
on divise le problème en deux à chaque tourO(log n)

Le tableau de synthèse du chapitre

AlgorithmeComplexitéTableau trié requisSur 1000 éléments
Recherche séquentielleO(n)non~500 comparaisons
Recherche dichotomiqueO(log n)oui~10 comparaisons
Tri par sélectionO(n²)non~500 000 comparaisons
Tri à bullesO(n²)non~500 000 comparaisons
Ce que la complexité ne dit pas

O(n²) ne signifie pas « lent ». Sur 10 éléments, un tri quadratique est instantané et parfaitement acceptable.

La complexité décrit comment le coût grandit avec les données, pas la vitesse absolue. Un O(n²) reste raisonnable sur un petit tableau et devient inutilisable sur un million de lignes : c'est cela qu'elle permet d'anticiper, avant d'écrire le code.

En production, on n'écrit pas ses tris

Array.Sort(t) en C# trie en O(n log n), bien mieux que vos deux tris. On étudie le tri par sélection et le tri à bulles parce qu'ils sont simples à comprendre et qu'ils font toucher du doigt ce qu'est une complexité quadratique, pas parce qu'on les utilisera.

Session 13 : L'essentiel, ce qu'il faut retenir

Prérequis : les douze chapitres précédents

Objectifs pédagogiques

  1. Réviser l'ensemble du module à partir d'une fiche unique

Les bases

  • Un algorithme est une suite finie, précise et effective d'instructions. Il s'écrit avant le code, pas après.
  • Une variable a un nom, un type, une valeur. L'affectation se lit de droite à gauche : total ← total + 5 range dans total le résultat du calcul.
  • En C#, = affecte et == compare. C'est l'erreur numéro un.
  • Deux entiers divisés donnent un entier : 7 / 2 vaut 3. Pour une moyenne, forcer le réel avec / 3.0 ou (double).
  • % donne le reste : n % 2 == 0 teste si un nombre est pair.

Les conditions

  • Une condition vaut Vrai ou Faux. Un booléen se teste directement : if (estValide), pas if (estValide == true).
  • ET (&&) exige les deux ; OU (||) suffit d'une. Un intervalle s'écrit avec deux comparaisons : note >= 0 && note <= 20.
  • Dans une cascade de SinonSi, l'ordre décide du résultat : on commence par le seuil le plus restrictif. Une erreur d'ordre ne produit aucun message, seulement des résultats faux.
  • Selon / switch compare une variable à des valeurs exactes ; les intervalles restent au SinonSi.
  • En C#, mettez toujours les accolades, même pour une seule instruction.

Les boucles

  • Pour quand on sait combien de fois, TantQue quand ce peut être zéro fois, Répéter quand c'est au moins une fois, donc pour toute saisie contrôlée.
  • Un accumulateur s'initialise à 0 avant la boucle ; un maximum s'initialise avec le premier élément, jamais avec 0.
  • Dans tout TantQue, il doit exister une ligne qui rapproche de la sortie. Si vous ne la trouvez pas, la boucle est infinie.
  • Entre JusquÀ et while, la condition s'inverse : les comparaisons et le connecteur logique.
  • Deux boucles imbriquées multiplient le nombre de tours.

Les tableaux

  • Les indices vont de 0 à Length - 1. La dernière case est t[t.Length - 1], et la condition de boucle s'écrit i < t.Length.
  • Quatre motifs couvrent presque tout : additionner, chercher le maximum, compter, rechercher. Ils s'écrivent toujours pareil.
  • Tout ce qui se calcule en lisant chaque case une fois se calcule dans la même boucle.
  • Une position introuvable se code par -1, jamais par 0 qui est un indice valide.
  • Un tableau 2D se parcourt avec deux boucles imbriquées ; GetLength(0) donne les lignes, GetLength(1) les colonnes. L'emplacement de l'initialisation entre les deux boucles décide du résultat.

Les fonctions

  • Une fonction retourne une valeur, une procédure (void) produit un effet. Le test : « l'appelant a-t-il besoin du résultat ? »
  • Une fonction calcule et retourne ; c'est l'appelant qui décide d'afficher. Une fonction qui affiche ne sert qu'une fois.
  • Une variable déclarée dans une fonction n'existe que là. C'est une protection, pas une contrainte.
  • Les arguments passent par valeur : la fonction reçoit une copie. ref et out passent la variable elle-même. Les tableaux font exception : ils sont toujours modifiables.
  • Un bloc qu'on ne sait pas nommer en trois mots fait deux choses : il faut le couper.

Rechercher et trier

  • La recherche séquentielle est en O(n) et fonctionne sur n'importe quel tableau. La dichotomique est en O(log n) mais exige un tableau trié ; sinon elle répond faux, sans erreur.
  • Le tri par sélection cherche le minimum restant ; le tri à bulles échange les voisins. Les deux sont en O(n²).
  • On reconnaît la complexité à l'œil : une boucle donne O(n), deux boucles imbriquées donnent O(n²), diviser en deux à chaque tour donne O(log n).
  • La complexité décrit comment le coût grandit avec les données, pas la vitesse absolue. Un O(n²) est parfait sur 10 éléments et inutilisable sur un million.
  • En production, on utilise Array.Sort : on étudie ces tris pour comprendre, pas pour les employer.
